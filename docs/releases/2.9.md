# Cube Run 2.9 — 2026-10-15

## Crash correction

The supplied Android 10 report identifies a `ConcurrentModificationException` in
`CubeRun.collide()` while iterating `Track.rows`. A Space portal can start the
Black Hole challenge from that loop; resetting the challenge may remove its old
exit row and starting it appends a new exit row. Both operations structurally
modify the same `ArrayList` before the iterator finishes.

The challenge reset/start is now deferred to the collision pass's `finally`
block. Ordinary Space/world transitions outside collision still start
immediately. The implementation does not copy the row list each frame. A unit
regression test uses a real `Track` to verify that replacing a challenge exit
while iterating completes without invalidating the iterator.
